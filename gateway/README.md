# Sensor Watch Gateway

FastAPI-сервис, который принимает телеметрию сенсоров, прогоняет её через потоковый монитор качества и свежести и отдаёт статусы, инциденты и журнал объяснений по REST и Server-Sent Events.

Монитор — порт `demo/engine.js` на Python. Тест `tests/test_engine.py` проверяет, что на всех сценариях результаты совпадают с JS-движком: сообщения, кадры, события, инциденты и метрики.

## Запуск

```sh
cd gateway
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --port 8000
```

Документация OpenAPI: `http://127.0.0.1:8000/docs`.

Если собран фронтенд (`frontend/dist`), gateway раздаёт его с того же порта: `http://127.0.0.1:8000/`.

Тесты (для проверки совпадения с JS нужен Node.js):

```sh
.venv/bin/python -m pytest
```

## Устройство

- **Такт.** Фоновая задача раз в `GATEWAY_TICK_INTERVAL` секунд вызывает `Monitor.tick` для каждого сенсора. Таймер свежести работает и без входящих сообщений.
- **Часы.** У сенсоров телеметрии время — секунды Unix (`clock: wall`). У симуляций — модельные секунды от начала сценария (`clock: virtual`). Симуляция проходит сценарий со скоростью `speed` модельных секунд за секунду реального времени.
- **Время получения** назначает gateway. Время измерения сенсора больше чем на `GATEWAY_MAX_FUTURE_SKEW` секунд в будущем отклоняется: часы сенсора спешат.
- **Состояние** хранится в памяти процесса. Истории кадров, измерений и событий — кольцевые буферы ограниченного размера.
- **Конкурентность.** Реестр изменяется только из цикла asyncio. Тяжёлые `replays` и `benchmark` выполняются в пуле потоков и реестр не трогают.

## API `/api/v1`

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Работоспособность, число сенсоров, симуляций и подписчиков |
| GET | `/meta` | Параметры детектора, эталоны режимов, сценарии, лимиты, границы seed и рекомендуемые seed |
| GET | `/overview` | Сводка статусов и открытых инцидентов по всем сенсорам |
| POST | `/telemetry` | Пачка измерений (до 5000). Ответ `202`: принято и отклонённые с причиной |
| GET | `/sensors` | Список сенсоров с текущим статусом |
| GET | `/sensors/{id}` | Сенсор, эталоны; для симуляции — разметка сценария |
| DELETE | `/sensors/{id}` | Удалить сенсор и историю |
| GET | `/sensors/{id}/frames` | История кадров монитора (`since`, `limit`) |
| GET | `/sensors/{id}/measurements` | Полученные измерения (`since` по времени получения) |
| GET | `/sensors/{id}/events` | Журнал объяснений (`after_seq`) |
| GET | `/sensors/{id}/incidents` | Инциденты сенсора (`type`) |
| GET | `/incidents` | Инциденты всех сенсоров (`sensor_id`, `type`, `state`, `limit`) |
| POST | `/simulations` | Запустить сценарий как живой сенсор |
| GET | `/simulations`, `/simulations/{id}` | Состояние симуляций |
| DELETE | `/simulations/{id}` | Остановить симуляцию; история сохраняется |
| POST | `/replays` | Детерминированное воспроизведение сценария с метриками |
| POST | `/benchmark` | Пакетная проверка: сценарии × диапазон seed |
| GET | `/stream` | SSE: `sensor_added`, `sensor_removed`, `update` (параметр `sensor_id`) |

Ошибки возвращаются как `{"detail": ...}`: `401` — нет ключа, `404` — объект не найден, `409` — конфликт ID, `413` — слишком большая пачка, `422` — ошибка валидации, в том числе seed вне диапазона 1…999 999 или не целое число, `429` — предел числа сенсоров.

Пример отправки телеметрии:

```sh
curl -X POST http://127.0.0.1:8000/api/v1/telemetry \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"sensor_id":"camera-01","event_time":'"$(date +%s)"',"value":95.2,"mode":"A","id":1}]}'
```

## Настройки

Переменные окружения с префиксом `GATEWAY_` (можно положить в `gateway/.env`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `GATEWAY_API_KEY` | не задан | Если задан, запись (`POST`/`DELETE`) требует заголовок `X-API-Key` |
| `GATEWAY_CORS_ORIGINS` | `["http://localhost:5173", "http://127.0.0.1:5173"]` | Разрешённые источники для браузера |
| `GATEWAY_TICK_INTERVAL` | `1.0` | Период такта монитора, с |
| `GATEWAY_FRAME_HISTORY` / `MEASUREMENT_HISTORY` / `EVENT_HISTORY` | `3600` / `3600` / `2000` | Размеры буферов на сенсор |
| `GATEWAY_MAX_BATCH` | `5000` | Сообщений в одной пачке |
| `GATEWAY_MAX_SENSORS` | `1000` | Предел числа сенсоров |
| `GATEWAY_MAX_FUTURE_SKEW` | `5.0` | Допуск опережения часов сенсора, с |
| `GATEWAY_MAX_SIMULATION_SPEED` | `60` | Максимальная скорость симуляции |
| `GATEWAY_MAX_BENCHMARK_RUNS` | `1000` | Прогонов в одном запросе `benchmark` |

## Ограничения

Одна копия процесса, без персистентности. После перезапуска состояние теряется. Эталоны режимов общие для всех сенсоров и заданы в коде (`app/engine/monitor.py`). Уведомления во внешние системы не отправляются.
