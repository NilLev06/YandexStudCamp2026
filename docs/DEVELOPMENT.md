## Окружение

| Инструмент | Требование | Проверенная версия |
|---|---|---|
| Python | ≥ 3.10, согласно `gateway/pyproject.toml` | 3.12.12 |
| Node.js | ≥ 18, для Vite и JS-тестов | 20.10.0 |
| npm | Для установки по `package-lock.json` | 10.2.3 |

Gateway: FastAPI 0.115.6, Uvicorn 0.32.1, Pydantic 2.10.3, pydantic-settings 2.6.1. Тесты: pytest 8.3.4, httpx 0.28.1. Версии закреплены в `gateway/requirements*.txt`.

Интерфейс: React 18.3.1, TypeScript 5.6.3, Vite 5.4.11, Gravity UI. Источник версий — `frontend/package.json` и lock-файл. Автономные сборка и тесты не требуют npm-пакетов. Docker, база данных и внешние сервисы для запуска не нужны.

Установка и запуск на macOS/Linux — в [README](../README.md#запуск). Используйте отдельное окружение `gateway/.venv`; активация не обязательна, если вызывать его Python по полному относительному пути.

### Windows / PowerShell

Из корня репозитория, первый терминал:

```powershell
cd gateway
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Нужен установленный Python 3.12 для команды `py -3.12`. Второй терминал из корня: `cd frontend`, затем `npm ci` и `npm run dev`. Активация окружения и изменение ExecutionPolicy не требуются. Сам проект проверен на macOS; команды PowerShell приведены для соответствующей структуры venv.

## Настройка интерфейса

Создайте `frontend/.env` по [`.env.example`](../frontend/.env.example), если нужны нестандартные параметры:

| Переменная | По умолчанию | Когда менять |
|---|---|---|
| `VITE_API_BASE` | `/api/v1` | Другой адрес или префикс API |
| `VITE_API_KEY` | Пусто | На gateway включён ключ записи |
| `GATEWAY_URL` | `http://127.0.0.1:8000` | Другой адрес gateway для dev-прокси Vite |

`GATEWAY_URL` читается из окружения процесса Vite, например `GATEWAY_URL=http://127.0.0.1:9000 npm run dev`. Переменные `VITE_*` читаются Vite из `.env` и встраиваются в сборку: после изменения перезапустите dev-сервер или пересоберите интерфейс. Для прямого обращения к другому origin добавьте адрес интерфейса в `GATEWAY_CORS_ORIGINS`.

## Команды проверки

Из корня репозитория:

```sh
node --test demo/engine.test.cjs
node demo/build.cjs
node demo/validate.cjs
```

| Команда | Что проверяет / создаёт |
|---|---|
| `node --test demo/engine.test.cjs` | Поведение монитора, seed, сценарии, ступени, здоровые потоки, актуальность сборки |
| `node demo/build.cjs` | Встраивает `engine.js` в `ui.html`, записывает `demo/index.html` |
| `node demo/validate.cjs` | Проверяет рекомендации seed и перезаписывает `docs/VALIDATION.md` |

Если меняли движок или UI, сначала пересоберите демку, затем запускайте тесты: они проверяют совпадение готового HTML с исходниками.

Gateway, из `gateway/` после установки `requirements-dev.txt`:

```sh
.venv/bin/python -m pytest
```

Проверяются API и ключ доступа, фильтрация телеметрии, такты без сообщений, SSE, лимиты, совпадение Python с JS и живых симуляций с replay, матрицы сценариев и seed. Для сравнения реализаций `node` должен быть доступен в PATH.

Интерфейс, из `frontend/`:

```sh
npm run typecheck
npm run build
```

`build` уже включает проверку TypeScript, затем создаёт `frontend/dist`. `npm run preview` позволяет посмотреть готовую сборку, но прокси `/api` настроен только для dev-сервера; для готового приложения с API используйте gateway. Отдельного набора UI-тестов в репозитории нет.

После сборки проверьте вручную: старт симуляции, обновление карточки и графиков, появление инцидентов, остановку, replay и benchmark. Обе темы и узкий экран проверяются через интерфейс.

## Сценарии и метрики

Контракты генератора, расписание событий, правила сопоставления и метрики описаны в [backend-спецификации](BACKEND-SPEC.md#generator--генератор-синтетических-данных).

Рекомендуемые seed выбраны на диапазоне 1…1000: эталон 42, быстрое и медленное обнаружение, незакрытый инцидент и максимум CUSUM без тревоги. Доступны в `/meta` и обоих интерфейсах; тесты проверяют рекомендации.

## Отчёт валидации

[VALIDATION.md](VALIDATION.md) создаётся скриптом, вручную его не редактируют. Он включает 5 сценариев × 1000 seed, ступенчатое снижение × 200 seed и длинные здоровые потоки с тремя моделями шума. Это отчёт JS-движка; соответствие Python проверяется отдельными тестами.

В отчёте есть незакрытые до конца записи инциденты и ложные тревоги на AR(1)-шуме. Упомянутый эксперимент с односторонним восстановлением — отдельный расчёт, не действующее правило детектора. Изменения текста отчёта вносятся в `demo/validate.cjs` с повторной генерацией.

## Частые проблемы

| Симптом | Проверка |
|---|---|
| «Gateway недоступен» | Процесс слушает 8000, `/api/v1/health` отвечает; `GATEWAY_URL` совпадает с адресом |
| На 8000 нет интерфейса | Выполнен `npm run build`; gateway перезапущен после появления `dist` |
| На странице нет сенсоров | Запустить симуляцию или отправить телеметрию; реестр изначально пуст |
| Запись возвращает 401 | Передать `X-API-Key`; для UI задать `VITE_API_KEY` и перезапустить / пересобрать |
| Сенсор остаётся `stale` | Передаются секунды Unix, часы согласованы; старая пачка не восстанавливает свежесть |
| Изменения JS не видны в демке | Выполнить `node demo/build.cjs`, открыть `demo/index.html` |
