# Frontend-спецификация — Sensor Watch UI

[README](../README.md) · [Техническая спецификация](TECHNICAL-SPEC.md) · [Backend](BACKEND-SPEC.md) · [Разработка](DEVELOPMENT.md)

В проекте два интерфейса: React-приложение для gateway и автономная HTML-демонстрация. Они используют один алгоритм мониторинга, но разные источники данных и способы воспроизведения.

## React-приложение

React 18, TypeScript, React Router, Gravity UI UIKit / Navigation / Charts. Точка входа — [main.tsx](../frontend/src/main.tsx), оболочка и маршруты — [App.tsx](../frontend/src/App.tsx). Для работы нужен gateway; готовая сборка может раздаваться им с одного адреса.

### Страницы

| URL / компонент | Данные и действия |
|---|---|
| `/` — `OverviewPage` | Список сенсоров, распределение качества и свежести, число инцидентов, запуск симуляции, переход к карточке |
| `/sensors/:sensorId` — `SensorPage` | Статусы качества / свежести / флагов, режим и эталон, возраст, доставка, измерения и CUSUM, разметка симуляции, журнал, инциденты; остановка симуляции и удаление сенсора |
| `/incidents` — `IncidentsPage` | Общий список и шкала по часам gateway, фильтры типа и состояния; переход к карточке сенсора |
| `/analysis` — `AnalysisPage` | Replay по сценарию и seed, рекомендуемые seed, графики и метрики двух методов; benchmark по выбранным сценариям и диапазону seed |

`SimulationDialog` задаёт сценарий, seed и скорость; после создания открывает карточку. `SeedField` проверяет целочисленность и границы из `/meta`. Benchmark дополнительно проверяет порядок границ, наличие сценариев и предел числа прогонов. Ошибки отображаются в Alert; результаты операций карточки — через Toaster.

### Загрузка и живые обновления

1. `App` запрашивает `/meta` и передаёт ответ через `MetaContext`. Пока ответ не получен, показан Loader; при ошибке — сообщение о недоступности gateway.
2. Обзор получает `/sensors`. Карточка параллельно запрашивает сводку, измерения, кадры, события и инциденты. Общий список инцидентов загружается отдельно.
3. `useStream` открывает `EventSource` и слушает `sensor_added`, `sensor_removed`, `update`. Карточка подписывается с `sensor_id`; обзор и инциденты — на все сенсоры.
4. Обзор заменяет сводку сенсора. Карточка добавляет измерения и кадры, оставляя последние 3600 элементов каждого массива; события добавляет только с новым `seq`. Массив событий в состоянии карточки не ограничен этим лимитом.
5. После событий открытия / закрытия карточка перечитывает инциденты. Общая страница перечитывает список с задержкой 500 мс, объединяя частые сигналы. Удаление текущего сенсора возвращает пользователя к обзору.

`useAsync` хранит загрузку, ошибку и данные; номер поколения запроса не позволяет запоздавшему ответу заменить более свежий. HTTP-клиент преобразует ошибки `detail` в `ApiError`. Все сетевые вызовы находятся в [api/client.ts](../frontend/src/api/client.ts), типы — в [api/types.ts](../frontend/src/api/types.ts).

EventSource переподключается автоматически, но SSE не повторяет потерянные сообщения. Клиент не перечитывает весь снимок при каждом reconnect: после разрыва возможны пропуски истории до перезагрузки страницы.

### Графики и журнал

| Компонент | Отображение |
|---|---|
| `MeasurementsChart` | Измерения по `event_time`, нормы режимов, инциденты и опциональная разметка. В анализе дополнительно показаны порог и его тревоги |
| `CusumChart` | S по времени обработки, границы `h` и `suspect` из `/meta` |
| `DonutChart`, `GroupedBarChart` | Распределение статусов и сравнение счётчиков |
| `IncidentTimeline` | Инциденты по `opened_at/closed_at` в Unix-времени gateway |
| `EventLog` | События от новых к старым: по умолчанию последние 30, в replay — 12 |

Пустые графики показывают «Данных пока нет». При отображении используются часы сенсора: Unix для внешней телеметрии и модельные секунды для симуляции. Высота графика измерений по умолчанию 320 px, CUSUM — 180 px; размеры и данные задаются в [components/charts.tsx](../frontend/src/components/charts.tsx).

### Темы, адаптивность и конфигурация

Светлая / тёмная тема переключается в боковой панели. Выбор сохраняется в `localStorage` под ключом `sensor-watch-theme`; без него учитывается системная тема. На ширине ≤ 800 px навигация сворачивается, CSS на ≤ 700 px перестраивает сетки и панели.

`VITE_API_BASE` и `VITE_API_KEY` задают адрес API и заголовок для записи; dev-прокси использует `GATEWAY_URL`. Значения, сборка и запуск — в [руководстве разработчика](DEVELOPMENT.md#настройка-интерфейса). Ключ в браузерной сборке не является секретом пользователя.

## Автономная демонстрация

Исходник — [demo/ui.html](../demo/ui.html), готовый файл — [demo/index.html](../demo/index.html). Vanilla JS и SVG, без CDN и сторонних пакетов. Работает при открытии локального файла; к gateway не подключается.

### Макет и управление

```text
Панель сценария, seed, скорости и запуска
Рекомендуемые seed, ползунок времени, ключевые моменты
Три статуса: качество, свежесть, доставка
Графики измерений / CUSUM, контекст, телеметрия, журнал
Итоговые метрики, проверка 250 прогонов, экспорт JSON
```

Верхний статус доставки вычисляется по `sinceReceipt`; это отдельный индикатор от свежести и от поля `flags` движка. Отдельной верхней панели флагов в автономной демке нет.

`load()` выполняет полный `replay()`. Ползунок и кнопки моментов выбирают готовый кадр и ставят показ на паузу. Ручное изменение корректного seed сохраняет текущую отметку времени; выбор рекомендации и смена сценария начинают с нуля. Некорректный seed не заменяет текущий поток.

`requestAnimationFrame` накапливает дробные модельные секунды в `carry`. При `carry ≥ 1` время продвигается на целую часть и вызывается `render()`. Скорости — 1×, 3×, 6×, 12×. Перемотка не пересчитывает историю решений; будущие измерения скрываются по времени доставки.

### SVG-графики и контекст

График качества использует X = `event_time`, шкалу Y = 30…102. Полученные точки сортируются по времени измерения; линия разрывается при расстоянии между соседними точками > 2 с. Слои показывают норму режима, опциональные аннотации и порог, тревоги, текущую отметку и tooltip с временами измерения / доставки. Фиксированная область графика обрезает значения вне шкалы, а не меняет исходные данные.

CUSUM строится по `Frame.now` до текущего момента, с порогом `CONFIG.h = 10` и динамической шкалой Y. Контекстная панель объясняет заданную фазу сценария; это пояснение расписания, а не отдельный детектор. Журнал показывает последние пять событий, случившихся к текущему времени.

При ширине графика < 500 px высота качества 250 px вместо 290 px, меньше подписей времени и скрыт текст аннотаций. CUSUM имеет высоту 125 px. `ResizeObserver` перерисовывает SVG; на ширине страницы ≤ 1050 px боковые панели уходят под график, на ≤ 650 px интерфейс становится одноколоночным.

### Результаты, benchmark и экспорт

Метрики сценария показываются в конце записи; кнопка «Перейти к итогу» сразу выбирает последний кадр. Используется `evaluate(result)`, определения — в [backend-спецификации](BACKEND-SPEC.md#evaluator--метрики).

Пакетная проверка выполняет 5 сценариев × seed 1…50. `setTimeout(..., 30)` даёт браузеру показать состояние ожидания; сами расчёты затем идут синхронно в основном потоке и могут временно задерживать UI. Итог кешируется в `benchmarkCache` на время открытой страницы.

Экспорт JSON содержит config, profiles, scenario, seed, metrics, messages, truth, incidents, events, baseline. Это результат полного сценария даже при экспорте из середины показа. В React-интерфейсе кнопки экспорта и перемотки автономной демки не реализованы.

### Сборка

Из корня: `node demo/build.cjs`. Скрипт заменяет `/* ENGINE_SLOT */` содержимым движка внутри уже существующего тега `<script>` в `ui.html`, затем пишет `demo/index.html`. Дополнительные `<script>` вокруг подстановки не добавляются. Глобальный `SensorDemo` используется UI для replay и оценки.

Сборка React-приложения выполняется отдельно: `cd frontend`, затем `npm ci` и `npm run build`. Два интерфейса не собираются друг из друга. [Проверки и ограничения тестирования](DEVELOPMENT.md#команды-проверки).
