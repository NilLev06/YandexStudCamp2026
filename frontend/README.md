# Sensor Watch - интерфейс

React 19 + TypeScript + Vite, дизайн-система [Gravity UI](https://gravity-ui.com):
`@gravity-ui/uikit` (компоненты), `@gravity-ui/navigation` (AsideHeader), `@gravity-ui/charts` (графики), `@gravity-ui/icons`.

```sh
npm install
npm run dev      # http://localhost:5173, /api и /docs проксируются на шлюз :8000 (GATEWAY_URL=... чтобы сменить)
npm run build    # dist/ - его раздаёт сам шлюз на :8000
```

Два режима:

- **Простой** (`/`): одна страница для показа. Сверху карточки 7 групп ошибок (те же номера, что в документе «Ошибки датчиков - математическая база»), под ними плеер сценария, один график, живая фраза-объяснение решения монитора, три светофора (качество, свежесть, доставка) и карточка группы с формулой из документа. Группа 7 показывает живой поток с дрона.
- **Эксперт** (`/expert`): все экраны ниже.

| Экран эксперта | Что показывает |
|---|---|
| Обзор | Сводка, карточки датчиков с живыми статусами, запуск сценария как потока, последние решения монитора |
| Датчик | Качество / свежесть / доставка / диагностика, график измерений (норма, медиана окна, порог, полосы инцидентов, разметка) и CUSUM, журнал, инциденты, эталоны и параметры, оценка по разметке |
| Инциденты | Все инциденты с фильтрами, «Принять» с комментарием оператора |
| Сценарии и проверка | Офлайн-прогон с перемоткой и ключевыми моментами, пакетная проверка 8 × N seed, запуск живого потока |
| 7 групп ошибок | Таблица групп как в документе + ответы на вопросы кейса |

Живые данные идут по одному WebSocket (`src/api/live.ts`), REST-клиент - `src/api/client.ts`.
Время модельных сценариев показывается как мм:сс от начала, живых источников - местное время.
